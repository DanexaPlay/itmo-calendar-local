# Частые вопросы и ошибки

### Календарь не найден: `icloud_calendar_missing_or_duplicate_name`

Открой iCloud.com и проверь точное **имя**, регистр и алфавит. Например, `ITMO` (латиница) и `ИТМО` (кириллица) не совпадают. Если календарей с одинаковым именем два, выбери уникальное имя и обнови `.env` **до привязки**.

### `icloud_bind_requires_empty_dedicated_calendar`

Программа намеренно не привязывает календарь с чужими событиями. Создай новый отдельный пустой календарь. **Не удаляй существующие личные события ради установки.**

### Ошибка подключения CalDAV / Apple App Password

Проверь Apple ID, пароль **для приложения**, доступ к iCloud Calendar и интернет. Никому не показывай содержимое `.dpapi`, `.env` или HTTP-логи. Не сбрасывай привязку наугад.

### `browser_no_schedule_response_login_or_site_navigation_required`

Открой ручной вход:

```powershell
.\.venv\Scripts\python.exe -m itmo_local browser login
```

После входа открой «Расписание» в новом окне Edge/Chrome. Если сайт не отвечает или блокирует автоматизацию, прекращай попытки обхода и проверяй доступ обычным браузером.

### `browser_session_rejected_by_itmo` / `browser_schedule_rate_limited`

Первое означает отказ в сессии; войди снова обычным способом. Второе — ограничение частоты запросов; останови повторные запуски, соблюдай требования сервиса. Программа не должна обходить rate limits или CAPTCHA.

### `browser_expanded_date_coverage_incomplete`

Сайт не сообщил один или несколько дней. Программа отказывается считать их пустыми и **не изменяет iCloud**. Проверь расписание на сайте; если изменился формат API, сообщи об ошибке без личного JSON.

### `browser_overlapping_responses_disagree`

Ответы для одного дня различаются между запросами. Это бывает при одновременном изменении расписания или несовместимом формате; синхронизация безопасно прервана.

### `icloud_many_deletions_need_explicit_confirmation`

Это защита от массового удаления. Сначала повтори `browser check` и сравни расписание на сайте с предпросмотром. Не добавляй `--allow-large-deletion` без ручной проверки.

### События появились два раза

Проверь, что запущена одна копия приложения и нет второй подписки/импорта `.ics` с теми же парами. `icloud preview` должен показывать `create: 0` для уже опубликованных событий. Если локальная SQLite потеряна, **не привязывай заново** календарь с событиями: программа намеренно блокирует конфликтующие и «осиротевшие» UID.

### Перейти с Edge на Chrome

Используй `BROWSER_CHANNEL=chrome` в `.env`, но **не переключай канал на том же существующем профиле без резервной копии**. Потребуется новый ручной вход; обычный повседневный профиль Chrome не используется.

### Windows не запускает `SETUP.cmd`

Извлеки ZIP в обычную локальную папку; установи 64-bit Python 3.12/3.13; убедись, что запускаешь сценарий от своего обычного пользователя Windows. Скрипт использует PowerShell без администраторских прав. Не отключай защиту Windows глобально.

### Приложение работает на Mac/Linux?

Пока нет: на Linux поддерживаются только офлайн-демо и тесты. Реальная авторизация iCloud в этом проекте хранит пароль через **Windows DPAPI**, а фоновые задачи регистрируются через Windows Task Scheduler. Нужен отдельный порт для macOS/Linux.

### Что безопасно прикладывать к GitHub Issue?

Версию Windows/Python, команду, фиксированный код ошибки (`browser_...`, `icloud_...`), ожидаемый результат и **синтетический** пример. Не загружай `.env`, JSON реального расписания, HAR, скриншоты вкладки Network, cookies, токены, DPAPI-файлы или SQLite.
