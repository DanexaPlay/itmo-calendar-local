# Авторизация ITMO.ID: browser-режим и официальный OAuth

**Основной режим v0.5.0 — `ITMO_AUTH_METHOD=browser`.** Он открывает
официальный my.itmo в отдельном профиле браузера Playwright. Пользователь
самостоятельно проходит вход/MFA на сайте. Python не запрашивает пароль
университета, не экспортирует cookies, Authorization, access/refresh-токены.
При последующих запусках используются данные того же изолированного
браузерного профиля Windows. Если сессия истекла, нужно вручную войти снова.

В фоне программа по исходному авторизованному запросу сайта выполняет
до четырёх дополнительных **GET** на тот же HTTPS-эндпоинт персонального
расписания, меняя только даты. Авторизация и ограничения сервиса остаются
обязательными. Это **неофициальная** интеграция: разрешённость автоматизации
определяют применимые правила ИТМО, а фактическая поддержка API не
гарантируется. Никакого обхода rate limits, CAPTCHA, MFA или блокировок.

## Альтернативный OAuth-режим (для разработчиков)

Код содержит экспериментальный `ITMO_AUTH_METHOD=oauth` с Authorization
Code + PKCE и loopback callback. Но для него нужен **собственный
зарегистрированный и разрешённый OAuth-клиент ITMO.ID**, имеющий доступ к
персональному расписанию. Нельзя заимствовать `client_id` официального сайта,
копировать токены из DevTools или обходить регистрацию.

[Документация ITMO.ID](https://docs.itmo.id/auth/oidc/requests) описывает
`client_id`, `redirect_uri` и запросы кодов/токенов. Она сама по себе не
разрешает использование какого-либо клиента сторонним приложением.

## Как защищать сессию

Папка `%LOCALAPPDATA%\PersonalItmoCalendar\itmo-browser-profile` содержит
данные авторизованного браузера. Никогда не загружайте её в GitHub, не
отправляйте в чаты и не переносите в OneDrive. Шифрование диска (BitLocker)
и защита учётной записи Windows снижают риск при потере ноутбука.
Удаление папки локально не отзывает сессию на стороне ИТМО. При подозрении
на компрометацию завершите сеансы через официальный сервис.
